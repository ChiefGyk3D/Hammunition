# BRouter routing (D-063) Implementation Plan

> **For agentic workers:** executed inline with superpowers:executing-plans,
> test first for every task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** carry BRouter as a pinned binary unit, build its `.rd5` routing
files from the station's regions with Copernicus elevation through a new
`brouter-mapcreator` converter, and register it in QMapShack from the
`qmapshack-offline` launcher.

**Architecture:** the Routino converter's shape (one build over every region,
one working directory and lock under `Staging`, all-or-none publish, a record
that forces a rebuild), with elevation steps per 5°×5° square before the
three map-creator phases. Three catalog units: `brouter` (binary tree),
`brouter-mapcreator-profiles` (data), `brouter-segments` (derived).

**Tech stack:** Python 3.11, pydantic schema, pytest with fake tools on
`PATH` (`tests/fake_tools.py`), mypy --strict, ruff.

**Spec:** `docs/superpowers/specs/2026-09-29-brouter-design.md`.

**Machine rules:** every command under `nice -n 19 ionice -c 3`; pytest with
`-p no:cacheprovider`; no GUI; no sudo; no real install; public example
regions and `N0CALL` only.
