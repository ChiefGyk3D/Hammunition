# Navigation, piece 2: trails, terrain and offline routing on foot

**Status:** design approved by the maintainer in conversation 2026-09-28
("sounds good go for it"); this document is written for the record and for
the implementation plan.
**Decision record:** D-061, written with the implementation. It extends D-057
(regions, freshness, derived data) and D-049 (pinned data units).
**Origin:** the maintainer, 2026-09-28, after Navit ran on the field laptop:
"need maps for trails, and such too. Think survival and EMCOMM."

Everything below was **measured on 2026-09-28** on the development host
(Parrot 7, Debian 13 base) with one already-installed region's `.osm.pbf`,
nothing installed, every tool run from the archive's own `.deb`. Times are
for that one US-state-sized region and are estimates for others.

## 1. What this piece delivers

| Need | Answer | Measured |
|---|---|---|
| See trails, tracks, footpaths with landuse and water | **QMapShack** rendering a Garmin `.img` built by `mkgmap` from the region already installed | Rendered under Xvfb: roads, landuse, water, place labels, a route on top |
| Plan a route on foot, offline | **Routino**, foot profile, run in-process by QMapShack | 5–39 ms per 10–17 km route, returned as GPX |
| Terrain: hillshade, slope, contours | **Copernicus GLO-30** elevation tiles, pinned; a VRT for QMapShack's hillshade and slope; contour lines as a raster overlay built with GDAL | VRT listed in the DEM dock; contour overlay rendered; hillshade drawing itself **not yet confirmed** |
| Record and load GPX tracks, waypoints, elevation profiles | QMapShack, natively | Read from its shipped help |
| Live position on the map | QMapShack's NMEA-over-TCP input, fed from gpsd by a loopback bridge | Bridge to be measured in the build |
| Find a street address offline | **Navit** (piece 1), the only tool here that can | See D-057 and §7 |

All from Parrot's archive: `qmapshack` (1.17.1; 1.21.1 in backports, which
D-038 resolves on a machine already taking packages from there, disclosed in
the plan), `routino` 3.4.3, `gdal-bin` 3.10.3, `mkgmap`, `mkgmap-splitter`,
`socat`. Nothing is built from source. Viking, Marble, GPSPrune and JOSM were
measured and are not carried: Debian's Viking renders nothing offline and
routes only through web services; Marble's offline place index has no
packaged builder; GPSPrune and JOSM use online tiles.

## 2. Units

### `osm-garmin` (derived, converter `mkgmap`)

One Garmin image per region, from the region's installed `.osm.pbf`
(`osm-regions`, D-057): `mkgmap-splitter` into tiles (48 s), then `mkgmap`
with its `default` style (126 s), which already draws and routes
`highway=path|footway|track|bridleway`, `sac_scale` and `tracktype`. Output
`<region>.img`, **0.85× the `.pbf`**, under
`/usr/local/share/hammunition/data/osm-garmin/`. Runs as the operator in a
staging directory like `osm-navit`, per-region failure contained, scratch
tiles removed after a successful build.

Not passed: `--index` and `--housenumbers`. They need mkgmap's upstream
bounds files, which have no published checksum, and QMapShack does not read
that index anyway. Recorded as a gap (§7).

### `osm-routino` (derived, converter `routino-planetsplitter`)

**One Routino database over every installed region**, so a route may cross
from one region into the next: `planetsplitter --parse-only` per region, then
one `--process-only`, prefix `hammunition`, output under
`/usr/local/share/hammunition/data/osm-routino/` (**0.67× the sum of the
`.pbf` files**, 83 s for one region). The trade: a region that fails to parse
fails the database rather than only itself; the step says which region and
why. Routino's `foot` profile from `routino-common` is used unchanged.

### `dem-copernicus` (data, method `dem-tiles`, provider `copernicus-glo30`)

Elevation tiles for the bounding box of every installed region, read from
each `.osm.pbf` header (piece 1's `osm_pbf.header_bbox`): one 1°×1° Cloud
Optimised GeoTIFF per square, about **39 MB each**, from
`https://copernicus-dem-30m.s3.amazonaws.com/`. Licence: the Copernicus DEM
licence, free worldwide with attribution, printed in the plan beside the size.

Verification, in D-057's two modes:

- **sha256, pinned by Hammunition**, from `catalog/data/copernicus-glo30-pins.yaml`,
  generated by `scripts/gen_copernicus_pins.py` for named regions. Each pin
  costs one download to compute, so the file grows as the maintainer runs the
  generator; the initial set covers the regions pinned yearly by D-057 as far
  as one run can reach, and the generator's `--check` runs in the weekly job.
- **MD5 from the publisher's object metadata; not pinned by Hammunition**,
  for a tile without a pin: the S3 ETag, which is the object's MD5 for a
  single-part upload, measured equal to `md5sum` on the test tile. The plan
  says which mode each tile gets, tile by tile, exactly as it does for
  regions. The bucket's own readme says tiles change only when its public tile
  list changes.

Which squares exist: the bucket's `tileList.txt` (about 26,000 names, ocean
squares absent) is carried as `catalog/data/copernicus-glo30-tiles.txt`, so
a square not in the list is *sea*, never an error, and the plan needs no
network to know it. The same generator refreshes the list; `--check` diffs it.

The plan prints tile count and total size per region; a US state is tens of
tiles, so hundreds of MB to a little over a GB. `update` prints counts only.

### `dem-qmapshack` (derived, converter `gdal-dem`)

From the tiles: `gdalbuildvrt` → `dem.vrt` (QMapShack's DEM for hillshade and
slope), and a contour overlay: `gdal_contour -i 20` (4 s per tile) →
`gdal_rasterize` to a Byte GeoTIFF (about 5 MB per tile) → `contours.vrt`, a
raster map QMapShack lists beside the Garmin image. The intermediate contour
GeoPackage (up to about 94 MB per mountain tile at 20 m) lives in staging and
is removed. Plain unlabelled lines: legible, not pretty. Labelled contours
inside the vector map need a DEM→OSM tool that is not in the archive
(`pyhgtmap` on PyPI is the candidate) and is a later, measured option.

### `qmapshack-offline` (launcher and per-user configuration)

A launcher that, before starting QMapShack, makes sure its per-user
configuration names our directories: the Garmin image directory, the DEM
directory and the Routino database directory (the exact keys measured from
QMapShack's own ini in the build). Existing values are kept; ours are added
if absent; nothing else in the file is touched. Per-user and unprivileged,
like the menu files (D-050). QMapShack refuses to start when
`/usr/share/routino/translations.xml` is missing; apt supplies it through
`libroutino0 → routino-common`, and `doctor` says so if it is absent.

### `gps-tether` (launcher: gpsd → NMEA over TCP)

QMapShack has no gpsd client; its *GPS Tether* reads NMEA RMC/GGA from a TCP
host. A launcher starts `gpspipe -r` behind `socat`, **bound to 127.0.0.1
only**, on port 10110 (the conventional NMEA-0183 port), one client at a time,
and prints the host and port to enter in QMapShack. It runs only while the
operator runs it; nothing is installed as a service. The guide says how to
connect, and that Navit needs none of this.

### The `navigation` profile

Gains `qmapshack`, `routino`, `gdal-bin`, `mkgmap`, `mkgmap-splitter`,
`socat`, `osm-garmin`, `osm-routino`, `dem-copernicus`, `dem-qmapshack`.
Piece 1's units are unchanged. No regions set → every map and DEM unit
defers by name, the viewers still install (D-035, D-049 rule 3).

## 3. Schema

- `DerivedDataInstall.converter` gains `mkgmap`, `routino-planetsplitter`,
  `gdal-dem`; `source` may name a `dem-tiles` unit as well as `osm-regions`.
- A new `DemTilesInstall` (`method: dem-tiles`, `provider: copernicus-glo30`,
  `licence`, `licence_url`), whose selection is the installed regions'
  bounding boxes; nothing is set by the operator beyond what D-057 already
  stores.

## 4. The plan, disk and time

The plan's *Map regions* section gains a *Terrain* block: tiles per region,
size, verification mode, licence; and the derived steps name their factors:
Garmin **0.85×**, Routino **0.67× of the sum**, contours **about 5 MB per
tile plus up to 94 MB per tile of scratch**. Every factor cites this document
and says "measured on one region". The disk check counts all of it.

## 5. Privacy

Tile names encode latitude and longitude, so they identify a region as
plainly as its name: they appear in the plan (local output, beside the region
names it already prints) and never in `update`, `doctor`, the bench page or a
commit. The tests use synthetic bounding boxes and tile names.

## 6. Tests

- Tile selection from a bounding box, including a box crossing 0° and the
  sea rule.
- Pin mode against MD5 mode per tile, and the plan's wording for each.
- Each converter's argv, staging, failure containment, scratch removal.
- The Routino multi-region parse/process sequence, and the one-region-fails
  outcome.
- The launcher's config edit: adds when absent, keeps existing values, touches
  nothing else, refuses a config it cannot parse.
- The bridge binds loopback only.
- Docs: the generated package pages, the guide's link check, the plan text
  golden with terrain.

## 7. Gaps, documented and carried

- **Offline address search is Navit's.** QMapShack's search is online only;
  Routino takes coordinates. The guide says: find the address in Navit, then
  plan the walk in QMapShack. (Piece 1's own address-search finding is
  recorded separately.)
- **Trail difficulty is not routed on.** Routino's foot profile ignores
  `sac_scale`; an alpine path scores as a footway. Said in the guide.
- **No hiking cartography.** The archive has no hiking style or TYP file;
  OpenTopoMap's and Freizeitkarte's are unmeasured upstream projects.
- **Garmin address index off** (bounds files unpinned).
- **Hillshade drawing unconfirmed** until the bench.
- **SRTM refused** (Earthdata login). **viewfinderpanoramas not carried**
  (no checksum, unclear licence). **USGS 3DEP** (public domain, US only,
  dated `historical/` URLs are immutable) is the alternative provider if
  anyone asks; the schema's `provider` enum leaves room for it.
- **BRouter** stays out: its jar is pinnable, its weekly routing data is not.

## 8. Out of scope

Kiwix and tile servers (piece 3); the EMCOMM knowledge base and local LLM
(#126); GPSPrune; online maps of any kind; a systemd service for the bridge;
labelled or baked-in contours; Garmin device export.
